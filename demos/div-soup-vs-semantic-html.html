Why Semantic HTML is Better

  1. Self-Documenting

    Semantic elements tell you what they are and what they do. No need for cryptic class names or excessive documentation.

  2. Built-in Functionality

    Elements like <details>, <dialog>, and <figure> come with native behaviors and accessibility features.

  3. Better Accessibility

    Screen readers and assistive technologies understand semantic HTML. No need for extra ARIA attributes or JavaScript.

  4. Improved Performance

    Less code, fewer DOM nodes, and native functionality means better performance without JavaScript overhead.

document.querySelectorAll('.accordion-trigger')
    .forEach(trigger => {
        trigger.addEventListener('click', () => {
            const content = trigger.nextElementSibling;
            const isExpanded = 
                trigger.getAttribute('aria-expanded') 
                === 'true';
            
            // Toggle aria-expanded
            trigger.setAttribute(
                'aria-expanded', 
                !isExpanded
            );
            
            // Toggle content visibility
            content.classList.toggle('active');
            
            // Manage focus for accessibility
            if (!isExpanded) {
                content.setAttribute(
                    'tabindex', 
                    '0'
                );
                content.focus();
            }
        });
    });

Benefits of the Semantic Approach:
  • Built-in accessibility (no ARIA needed)
  • Native keyboard support
  • Hardware-accelerated animations
  • No JavaScript overhead
  • Maintains state automatically
  • Works without any styling
  • 99 fewer lines of code!

(4 points)

(3 points)

A Note on "Modern" Development


Often, developers recreate native functionality because they:

  • Don't know these elements exist
  • Think custom solutions are more "modern"
  • Want more styling control
  • Are following outdated patterns

But here's the truth: The most modern approach is using the platform's built-in features. They're:

  • Constantly improved by browser vendors
  • Tested across millions of users
  • Optimized for performance
  • Built with accessibility in mind
